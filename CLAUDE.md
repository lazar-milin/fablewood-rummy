# Fablewood Rummy contributor guide

## Commands and structure

Use Node.js 22.9 or newer. There are no runtime packages or build step.

- `npm start` loads `.env` if present and runs `server.mjs`, serving `public/` and the room API on `HOST` (default 127.0.0.1 locally, 0.0.0.0 when `RENDER=true`) and `PORT` (default 3010). Explicit `HOST` values take precedence. Startup logs show the actual binding and assigned port. `.env.example` lists the settings.
- `npm test` runs `node --test tests/*.test.mjs`. The HTTP tests use temporary ports 3011, 3013, 3015, 3017, 3019, 3021, 3023, 3031, and 3033; these must be free and localhost sockets must be allowed.
- GitHub Actions runs the same suite on pushes and pull requests.

Keep changes focused. Run the relevant tests, and run the complete suite before publishing a change. Check responsive UI work in a browser at phone and desktop widths. Do not restart an existing local server unnecessarily: room state lives in memory.

## Engine

`public/engine.js` is the shared, DOM-independent rules engine. `createGame()` deals a new state. `play()` validates an action and returns a cloned next state. `resolveMeld()`, opening search, and bot planning share the table's rules. `DEFAULT_RULES` supplies the Serbian Remi 51 defaults; README.md documents the selectable house rules.

Preserve unique card IDs and conservation of all 108 cards across hands, stock, discard, cut card, and melds. Animal suits are fox, hare, toad, and owl. Ranks remain numeric internally; H/B/Q/E are display labels only. Do not implement rule changes solely in the UI: validate them in the engine or server and cover rule edge cases in tests. Opening groups allow at most one joker; later new melds may use multiple jokers. `meldChoices()` enumerates legal run placements; action `assignments` declare their joker ranks and suits. Validate declarations against the player’s hand.

The first player begins with one extra card and discards without a draw. Opening is forbidden during the first lap. Later turns draw, optionally play melds, then discard. A final discard is required, including a finish from hand. Respect forced-opening draws, cut-card finishes, fixed run-joker positions, flexible set-joker animals, reclaimed-joker obligations, and host preferences. Bots take one validated engine action every two seconds, scheduled by `bot-scheduler.mjs`. Each phase publishes a fresh revision. Public `moves` events contain visible card faces or anonymous stock draws only; `player-flights.js` animates remote actions from player tiles and local draw/discard actions from the hand. Its active-flight registry rebinds hidden destinations after renders, retargets on scroll/resize, and restores shared targets only after their final flight. Discard arrivals use one temporary previous-top face, never a stack of historical cards. Manual discard drops retain their drag ghost until acceptance and settle from the release position; button-triggered discards keep the longer hand-to-pile flight. The Discard label opens the current pile in the regular right panel, latest first; passive history cards remain previewable and panel scroll/focus survive updates. Bots and timed-out turns use validated engine actions; `botMove()` falls back to a legal discard when a plan is rejected.

## Server and private state

`server.mjs` uses Node's HTTP server and a process-local `Map` of rooms. Room codes have eight hexadecimal characters. A bearer token identifies a seated human. Host-only changes and mode/phase restrictions are validated server-side. The room's `host` field holds the host's seat index. In the lobby the host always sits in seat 0, which local play logic rely on. In a running game a bot takes over a leaving player's seat, and a leaving host passes the host controls to the next player. A table is deleted only when its last player leaves. Player names come from `public/names.js` when omitted. Deals, reshuffles, and generated names use the server's `crypto.randomInt()`-based `random`; pass it to `createGame()`, `play()`, and `forestName()`.

Throw `PlayerError` (from `public/engine.js`) for messages meant for players; they answer 400. Any other error is a server fault: it is logged and answers 500 with a generic message, so never rely on a plain `Error` reaching the player. `limits.mjs` holds the per-address rate limits (1,800 API requests and 20 new tables a minute) and the 24-hour expiry of untouched tables; every room request updates `touched`. With `TRUST_PROXY=true` the limits count the address a single reverse proxy appends to `X-Forwarded-For`; otherwise that header is ignored, so clients cannot choose their own address.

All room responses go through `view()`. Never return the raw room or raw game state. In online play, other players' hand entries are replaced with `{hidden:true}`. Stock entries are always hidden. Local mode intentionally reveals human hands to the shared device while hiding bot hands. `local-play.js` keeps a solo human’s hand visible during bot turns and requires a pass-screen only with multiple human seats. Legacy hotseat/bot mode requests normalize to local (bot requests still populate bot seats). The cover starts below the header, is opaque from the turn strip down, and fades toward the top. A separate glyph mask shifts from purple at the top to gold at the bottom. Header controls and their floating panels stay above the cover. `fitPassCover()` measures header and turn boundaries on render, header reflow, scroll and resize. Seat tokens must not be exposed in public player lists or table listings. Keep the privacy and static-path traversal tests passing.

Only `public/` is served. The static handler resolves file paths inside that directory and rejects paths outside it. It sends types from its map (unknown types as `application/octet-stream`), `nosniff`, and weak ETags; art and fonts are cached for a week, and other files are revalidated on every load. Keep production notes, prompts, licences for the project, and contributor documents outside `public/`; font notices stay beside the publicly distributed fonts.

Duplicate starting-hand rules live in `public/duplicate-deals.js`. Count matching animal/rank pairs, excluding jokers. `createGame()` rejects deals meeting `dealDuplicateLimit` (0, 3, 4); the inclusive threshold must never escape to clients. `redealDuplicateLimit` queues qualifying humans before play. `deal-decision` is server-authorized for the current reviewer (the host handles local choices); block actions, bots and timers until the queue clears. A whole-table redeal retains the round, first player and scores, but increments `dealNumber` to reset local hand arrangements. Other views expose only the deciding seat, never their pair count or cards. Aces retain the engine’s low/high/both enum; the UI shows only Low and High toggles and disallows turning both off.

## Undo, turn boundaries, and scores

Undo is constrained to the current turn and cannot reveal the stock: a stock draw is not undoable, and a completed discard cannot be taken back after another player sees it. Actions after a visible discard draw may be undone if the host enabled Undo. Preserve server history and turn-backup handling rather than adding client-only rollback. Forced-opening/cut draws have a separate Cancel draw path.

`scoreRound()` records each completed round once through `awardRound()` in `public/win-conditions.js`, including per-round scores. Win condition is a boxed None / scoring-mode selector: round victories, cumulative scoring, or a 301/501 threshold. Threshold matches start another round after five seconds until any cumulative total reaches the limit; the lowest total then wins (ties share victory). Server-owned `nextRoundAt` drives the countdown and blocks manual rematches during it. A new match resets its totals and breakdown. `victory.js` shows the optional results after the final card flight. Totals accumulate and the first player rotates. The scoreboard is hidden until a round has completed. A timer completes an expired turn through legal automatic actions and clears obsolete undo history. During play only the host may change the timer through settings; reject every other live setting and mixed payload. Changed durations reset the current turn clock, including undo and draw-backup snapshots. Undo settings appear only in the lobby.

## Client and responsive layout

`public/app.js` renders the landing page, lobby, header, play surface, and preferences. It long-polls the same-origin HTTP API with `since=<revision>` (25-second wait, 204 when unchanged), keeping one request in flight and backing off after errors. Authenticated mutations send their base revision; a mismatch returns 409 with a fresh private view. Create/join admissions need no revision. State-changing actions are serialized through `run()`; `accept()` updates the room and renders. `public/packing.js` handles local hand grouping without changing game ownership or rule validity. The default interface replaces automatic packing with `movement-hand.js` (persistent ordered units, arbitrary groups, one-shot sorts) and `movement-pointer.js` (pointer capture after a 7px drag threshold). Provisional opening groups stay reserved in the engine hand by ID; `stage-open` validates each meld and automatically commits the full opening at the threshold. `reset-open` and `unstage-open` restore those reservations without cancelling the draw or its opening obligations. The public view exposes only the provisional cards themselves.

`public/index.html` loads the CSS layers in order: base, remi, fablewood, refinements, table layout, card art, card preview, then responsive overrides, movement styles and simple-card styles. Header controls retain 47px square collapsed buttons, expand labels on hover, and slide as one row. `fitHeader()` measures collapsed control widths so hovering does not change header layout. Player tiles move below when needed and center in that row. Their status text and reserved badge space must match between active and inactive players.

Turn descriptions wrap. When text and actions no longer fit together, natural-width action buttons form centered rows. Editable inputs remain selectable; game surfaces and artwork are otherwise not draggable/selectable. Preserve the Alagard title font and Woodland/VCR interface font. `public/card-preview.js` supports hover, touch hold, and keyboard inspection.

## Artwork pipeline

`public/card-art.js` and `public/card-art.css` compose the cards from vector sprites in `public/art/card-kit/assets/`. Both the game and `public/atelier/` use those same assets and the single font copies in `public/fonts/`. Do not duplicate fonts or artwork to add a new consumer. `setSimpleCards()` controls the personal launch-screen display preference; simplified faces are cached and reuse the original suit frame with a suit marker and rank. Simplified jokers use vertical JOKER letters without a marker, and the live `cardBackMarkup` export switches to the original back frame and glyph background with only a crescent marker for stock and anonymous flights. Card Atelier retains its artwork. The launch toggle is always expanded and has no icon. The mode label reflects the preference, and the launch toggle must not erase name/code drafts. Hard duplicate dealing limits clear and block optional redeal choices on the server as well as in the controls.

Art prompts and historical records belong in `docs/art/`, never in the served directory. `ASSETS.md` records current provenance and third-party font terms. `tools/px2svg.py` converts pixel artwork to real vector paths; its optional Python dependencies are Pillow and NumPy. Inspect the result in Card Atelier, preserve viewBox crops and proportions, and validate every local HTML/CSS asset reference before replacing files. Obsolete preview pages and unused sprites should be removed instead of kept publicly without navigation.

The project uses GPL-3.0-only. Third-party fonts retain the separate author permissions in `public/fonts/LICENSE-*.txt`; preserve attribution when changing the asset pipeline.

## GitHub issues

Use the repository's existing labels: `bug` for incorrect behavior, `enhancement` for new behavior, `documentation` for contributor/player documents, and `accessibility` for accessibility barriers. The repository also has standard triage labels such as `question`, `duplicate`, `help wanted`, and `good first issue`; do not assume area labels exist. Reference the issue numbers addressed by a commit or pull request and describe the final behavior plus validation. Only close an issue once its requested work is complete.

## Field-building experiment

This checkout uses `experiment/field-building` and port 3042. `field-building.js` handles `field-*` actions through the engine. Drafts reserve IDs in their owner’s hand (`fieldGroups`) and are exposed separately as public card faces by the server; never expose other unplayed hand cards. Only the current owner may edit. Field groups can be incomplete, combined, reordered, returned or have one card ejected. Valid groups automatically open together at the threshold or lay individually after opening; the engine still enforces every meld rule and a final discard. Failed field-play actions release the source group and return a fieldNotice without changing the permanent meld. Discard first releases unfinished field groups; if its own validation fails it retains the turn and reports the error. Bots and timer fallback release drafts before planning plays.

Returned badges are saved per hand in browser session storage, derived from public-field-to-private-hand transitions. They override New and clear on hover/click/drag. `ungroupCards()` makes single-card ejections and rejected returns loose; an entire draft dragged back to a hand gap remains grouped. Permanent table melds never have ejection controls. The baseline legacy opening-attempt actions remain available to bots/tests, but the experimental UI uses field groups.
